# Ctrl branding and selectable app icon

Date: 2026-10-10
Status: approved in chat

## Goal

Rebrand this fork from "T3 Code" to "Ctrl" with a keycap logo, and let each client choose
between three keycap icon designs. Keep the change shallow so upstream T3 Code merges stay easy.

## Icon designs

Three designs, all a single "ctrl" keyboard key on the existing black app-icon background:

- `outline` (A): line-drawn key, inset top face, "ctrl" legend lower-left.
- `solid` (B, default): bright physical key seen slightly from above, "ctrl" centered on the top face.
- `mac` (C): Apple-keyboard control key, "⌃" top-right, "control" lower-left.

Lettering is converted to vector paths (no runtime font dependency). Each design gets prod,
dev and nightly variants, keeping the existing per-channel tint conventions (dev = blueprint
background, nightly = nightly background, prod = black).

Reference mockup: `docs/superpowers/specs/2026-10-10-ctrl-branding/variants.html` (rendered: `variants.png`) (A/B/C SVGs at 128×128 viewBox).

## Where icons come from

- Bundled icons (Finder/Launchpad/.app, Windows installer, Linux, iOS/Android launcher, PWA,
  favicons in the built web app) are generated by the existing pipeline (`assets/*/app-icon.icon`
  Icon Composer projects → `vp run icons:export`) and always use **solid (B)**.
- The macOS 1024 PNG (`*-macos-1024.png`) normally needs Icon Composer's GUI; generate it with the
  same spec instead (1024×1024, opaque body 824×824 inset 100px, soft shadow) — never automate the GUI.
- The other two designs ship as additional assets used at runtime only.

## Setting

- New client setting `appIcon: "outline" | "solid" | "mac"`, default `"solid"`, beside the other
  appearance client settings (`packages/contracts/src/settings.ts`), shown in Settings → Appearance
  as "App icon" with a preview of each option.
- Runtime effects when the setting changes (and at startup):
  - In-app logos switch instantly: sidebar wordmark/mark, welcome wizard, loading/splash screens,
    timeline brand marks, mobile `BrandMark`/`CompactBrandTitle`/`LoadingScreen`/wordmark.
  - Desktop: dock icon (macOS, via the existing `app.dock.setIcon` path in `DesktopAppIdentity`)
    and window icon (Windows/Linux `BrowserWindow.setIcon`).
  - Web: the document favicon links are swapped live.
- Not switchable at runtime (documented limitation): the bundled .app/installer icon and the
  mobile launcher icon (alternate-icon native setup is out of scope).

## Rename

- Display name "T3 Code" → "Ctrl" through the existing central branding (`APP_BASE_NAME` and the
  desktop-injected branding, desktop product name, mobile app names "Ctrl", "Ctrl Dev", "Ctrl Preview").
- New desktop app id and mobile package/bundle ids under `com.nachogames.ctrl[.dev|.preview]`, and a
  separate default data directory (`~/.ctrl` instead of `~/.t3`) so Ctrl installs alongside official
  T3 Code without sharing state.
- Unchanged in this pass (merge cost / external registrations): `@t3tools/*` package names, the `t3`
  CLI binary name, `T3CODE_*` environment variable names, URL schemes used for OAuth/T3 Connect
  callbacks, and internal identifiers. User-visible strings that hard-code "T3 Code" outside the
  central branding are updated only where shown in primary UI (window titles, menus, onboarding,
  settings headers); doc strings and logs stay.
